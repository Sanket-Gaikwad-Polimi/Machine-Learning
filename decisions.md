# Design decisions

We wrote these decisions down while building the project (2026-10-25), before the test set was scored. Post-hoc findings are marked as such. Together with the rules in README.md (section 9), they show that no choice was tuned on test results.

## Brightness (from the EDA)
- Good test images are darker (mean ~0.67) than the training images (~0.72) and the defective test images (~0.73): risk of false positives.
- src/data.py has an optional per-image brightness normalisation flag, OFF by default, decided a priori, never tuned on test results.
- Robustness step: check score stability on the 40 validation images under brightness changes.
- Report both models with and without normalisation.

## Resolution
- Main results at 256 px. A larger size only as a reported comparison, never chosen by test scores. (In the end we did not run a larger size.)

## Thresholds (src/metrics.py, fixed a priori)
- Image threshold T_image = 99th percentile of the 40 validation scores; pixel threshold T_pixel = 99.9th percentile of all validation heat-map pixels.
- Caveat: with only 40 validation images, T_image lies between the two highest validation scores and depends on which images were drawn.

## Autoencoder (src/autoencoder.py, fixed a priori)
- 1 grey channel in [0, 1], no ImageNet normalisation, 256 px, bottleneck 32 x 8 x 8, MSE loss, Adam (lr 1e-3), 120 epochs, batch 8, seed 42.
- Training augmentation: random rotation (corners filled with the image's median grey) and flips.
- Best epoch = lowest loss on the 40 validation images.
- Heat-map = per-pixel squared error, Gaussian sigma 4. Score = maximum of the smoothed heat-map.
- Checkpoint: outputs/checkpoints/autoencoder.pt (autoencoder_bn.pt with brightness normalisation).

## PatchCore (src/patchcore.py, fixed a priori)
- wide_resnet50_2 IMAGENET1K_V1, frozen. Input 256 px, grey repeated to 3 channels + ImageNet normalisation.
- layer2 + layer3, 3x3 local average pooling, layer3 upsampled to 32 x 32, concatenated: 1536 dims per patch.
- Memory bank from the 280 training images only (286,720 patches), greedy coreset to 10% (seed 42, random projection to 128 dims used only for the selection).
- Patch score = nearest-neighbour distance; image score = maximum patch score; heat-map = bilinear upsampling to 256 + Gaussian sigma 4.
- No augmentation. Brightness flag off by default. Checkpoint: outputs/checkpoints/patchcore_bank.pt (patchcore_bank_bn.pt).

## Evaluation protocol (evaluate.py, fixed before any test image was scored)
- Variants: ae_raw, ae_bn, pc_raw, pc_bn (bn = brightness normalisation on). Missing ones are built from train/val only.
- Thresholds per variant from its 40 validation images, written to outputs/results/thresholds.csv before Phase B (test).
- Robustness perturbations (applied to the 256 px images in [0, 1], the same images for all variants): brightness -0.05 / +0.05, contrast x0.8 / x1.2 around the image mean, rotation 10 deg (corners filled with median grey), Gaussian noise sigma 0.02 (seed 42 + index). Measured on validation (score change, false-reject rate) and on test (AUROC, false-reject rate, recall at the fixed threshold).
- Example figures chosen by fixed rules: highest-scoring false positive, lowest-scoring missed defect, median-score detection of each defect type.
- The test set is scored once; afterwards only reporting/plotting code may change.

## The test run (2026-10-25)
- evaluate.py ran ONCE on the 160 test images (10.3 min). Frozen results: outputs/results/metrics.csv, per_defect.csv, robustness.csv, thresholds.csv, <variant>_scores.csv, evaluate_log.txt, and the test heat-maps (published in the Release).
- A normal rerun refuses to start. `python evaluate.py --report-only` only redraws tables and figures from the saved scores. `python evaluate.py --out-dir outputs/rerun` (added in the final step) repeats the whole evaluation in a separate folder without touching the official files.
- Any further analysis uses validation images only and must not change models, thresholds or the frozen results.

## Post-hoc diagnostics (diagnostics.py, validation images only)
- Frozen files unchanged (SHA-256 checked); thresholds read from thresholds.csv; no test image loaded.
- PatchCore's rotate_10 drop comes mostly from the flat grey corner wedges (wedges_only +68.6% vs rotate_10 +72.3%); a clean 10 deg rotation at 1024 px with reflect padding gives +8.9% (8/40 validation images above T).
- Noise sigma 0.02 added at 1024 px before resizing (camera-like) has no effect; the frozen noise test added it after resizing (unnatural texture, +41.9%).
- rot90 gives +31.7% for PatchCore (hypothesis, not tested: rotated lighting/background, never seen in training). The autoencoder reacts much less to these conditions.
- The identical rotate_10 AUROC of ae_raw and pc_raw (3537 of 4879 pairs) is a coincidence, not a bug (different scores: false-reject rate 0 vs 1 at their own thresholds).
- Reported as a labelled post-hoc analysis next to the frozen robustness numbers, never as a replacement.

### Phase 1: analysis of the frozen v1 results (analysis.py; written before it was run)
- Reads saved files only: <variant>_scores.csv, <variant>_val_scores.csv, thresholds.csv and metrics.csv (outputs/results), the test heat-maps outputs/checkpoints/<variant>_heatmaps.npz, and the masks (256 px, nearest-neighbour). No model is loaded and nothing is re-scored. Outputs go to outputs/analysis/ (CSV + PNG), labelled "post-hoc analysis of frozen v1 results". Self-check first: AUROC, recall, false-reject rate and IoU recomputed from these files must equal metrics.csv.
- Localisation, all 4 variants, the 119 defective test images: peak = position of the heat-map maximum at 256 px (the first one if tied). Distance = Euclidean distance in pixels at 256 px from the peak to the nearest defect pixel (0 inside the mask). Hit = distance <= 8 px, i.e. the peak lies in the mask dilated by a disk of radius 8 px (one PatchCore cell). Radius fixed a priori. Reported: hit rate overall, per defect type, and for detected images only (TP at the frozen T_image). For context, the chance level = mean share of the image covered by the dilated mask (the hit rate of a randomly placed peak).
- Threshold trade-off, hypothetical only (the official T stays): ROC and precision-recall curves from the test scores with the frozen T marked. Recall at test false-reject rates of at most 0%, 2.5%, 5% and 10%: with 41 good test screws that allows 0, 1, 2 and 4 false rejects, and the hypothetical T is the (k+1)-th highest good test score (decision: score > T). Validation-only alternative rules: T = max of the 40 validation scores; T = mean + 3 std of the 40 validation scores (sample std, ddof 1); their test recall and false-reject rate shown as what-if.
- Uncertainty: bootstrap with 2000 resamples, seed 42 (numpy default_rng), stratified: the 41 good and the 119 defective test images are resampled with replacement separately. The same resampled images are used for all 4 variants (paired). Metrics at the frozen thresholds: image AUROC, recall, false-reject rate, IoU (mean per-image IoU over the resampled defective images, as in metrics.csv). 95% CI = 2.5th and 97.5th percentiles. Paired bootstrap of the AUROC difference pc_raw - ae_raw, with its CI and the share of resamples where it is <= 0.

### Phase 2: synthetic defects on the validation images (src/synthetic.py + phase2.py; written before anything was generated or scored)
Purpose: a "validation set with defects", so Phase 3 can be judged without any test image. Everything below is fixed now and is not changed after scoring.
- Source: only the 40 validation images of split.json. No test image and no test mask is used.
- Defects are made on the original 1024 px image (float in [0, 1]), then rounded to 8 bit and resized to 256 px with PIL bilinear, exactly like data.load_image. The mask is made at 1024 px and resized with nearest-neighbour, exactly like data.load_mask. Reason: diagnostics.py showed that changes made at 256 px create textures no real photo has.
- Screw (foreground) rule, fixed: pixel darker than the image's median grey minus 0.30 (the median is the background, since the screw covers about 10% of the image); then binary closing (6 iterations), opening (3), keep the largest connected region, fill holes. Every defect is placed on this region: its centre must lie on the screw shrunk by 12 px, and the image is changed only inside the screw region, so the plain background is never touched. The mask = the defect shape cut to the screw region.
- Screw axis, for the thread damage: principal axis of the screw region; position t = 0 at the head and 1 at the tip. The head is the end whose outer 20% of the length contains more screw pixels (it is wider). Threaded part = t between 0.55 and 0.95.
- 4 types (sizes in px at 1024; "sign" is + or - with probability 1/2; all values uniform in the ranges):
  1. scratch: straight line, length 60-250, width 2-6, any angle; brightness change sign x 0.06-0.15, soft edges (Gaussian blur sigma 1). Mask = the line widened by 4 px on each side (1 px at 256: like a hand-drawn mask). At least 90% of the line must lie on the screw.
  2. spot (contamination): ellipse, half-axes 15-50, any angle; brightness change sign x 0.08-0.20, strongest in the centre and fading to 0 at the ellipse border. Mask = the ellipse.
  3. dent / missing material (CutPaste-style): rectangle, sides 30-90, filled with the patch of the same size copied from another point of the same screw (centre at least 1.5 x the longer side away); edges blended (alpha blurred with sigma 3). Mask = the rectangle.
  4. thread damage (smear): ellipse, half-axes 20-50, centre on the threaded part; the image there is replaced by a Gaussian-blurred copy (sigma 3-8), fading out towards the ellipse border. Mask = the ellipse.
- Size: defect area (mask at 256 px) between 0.1% and 1% of the image. Honest note: this range comes from the EDA defect-size statistics, which were measured on the TEST masks (median 0.29%, 118 of 119 below 1%). Only this size range is taken from the test set, never any score.
- Visibility: the largest grey-value change inside the mask at 256 px must be at least 0.03 (about 8 grey levels), so no "invisible" defect is counted. A draw that fails the area, on-screw or visibility rule is drawn again with the next random numbers (at most 500 draws).
- One defect of each type on each of the 40 images: 160 synthetic defective images with exact masks. Random numbers: numpy default_rng([42, image index, type index]), so each image is reproducible on its own. The images are generated on the fly and not stored; only a parameter table (CSV) and an example figure outputs/v2/phase2/synthetic_examples.png are saved. Example rule, fixed: validation images 0 and 20, all 4 types each (8 examples), shown as the full image with the mask outline, a crop before and after, and the mask.
- The example figure is checked by eye BEFORE scoring. If the defects look unrealistic or not subtle, the generator may be changed at that point (and this section updated), but never after any image has been scored.
- Baseline (phase2.py): the 4 frozen v1 variants, frozen T_image and T_pixel from thresholds.csv, nothing retrained. Scored: the 40 good validation images (must equal <variant>_val_scores.csv) and the 160 synthetic images. Reported per variant, per type and for all 160: image AUROC (40 good vs the synthetic ones), recall at T_image, pixel AUROC and IoU / Dice at T_pixel (src/metrics.pixel_metrics, on the good + synthetic images), localisation hit rate (heat-map maximum within 8 px of the mask, as in Phase 1) with the median distance and the chance level. Outputs in outputs/v2/phase2/ (CSV, PNG, log), labelled "synthetic defects on validation images". The 40 good images are the same ones that set T_image, so the false-reject rate here is about 1/40 by construction and is not a result.
- These baseline numbers are the yardstick for Phase 3. The generator is not tuned to make the synthetic results look like the real test results; any similarity or difference is only reported as an observation.
- Hash check: every file in outputs/results, outputs/figures, outputs/checkpoints and outputs/analysis is hashed (SHA-256) before and after; all must be unchanged.
- Example figure checked by eye (2026-11-13): the generator is accepted as it is, nothing changed.
- Note on IoU: scratch masks are wider than the changed line (4 px margin on each side at 1024), so the scratch IoU / Dice is pessimistic. IoU and Dice on synthetic defects are only compared between models (and between v1 and Phase 3), never read as an absolute quality.
- Limitation, stated before Phase 3: every synthetic defect lies at least 12 px inside the screw, and it is placed with the same screw rule that a background mask would use. So this set cannot show whether a background mask cuts off real defects at the screw's edge (e.g. manipulated_front, thread_side). Any Phase 3 background mask must therefore be dilated generously, and this risk must be stated when it is proposed.

### Phase 3a: groundwork for a second category (written before any code was changed)
No new model, no new experiment, no training. Only the code learns to handle more than one category; screw behaves exactly as in v1.
- Per-category settings live in one table, src/categories.py, decided now by reasoning, never from any score:
  - screw: data folder screw/, greyscale ("L"), 40 validation images, autoencoder augmentation = the v1 random rotations + flips (a screw may lie at any angle, so a rotated screw is still a good screw), background mask allowed = yes (the screw lies on a plain background, and v1 diagnostics showed false alarms on background marks), brightness target 0.72 (v1, from the 280 train images), defect types as in v1.
  - transistor: data folder transistor/, colour ("RGB": the case and leads differ in colour, and greyscale would throw that away), 40 validation images (173 train / 40 val from its 213 good training images, seed 42), autoencoder augmentation = none (in MVTec AD a rotated, shifted or flipped transistor is itself a defect, "misplaced"; augmenting would teach the model that such defects are normal), background mask allowed = no (a missing or misplaced transistor shows up on the background, so masking the background could hide exactly these defects), brightness target = not set yet (if a brightness-normalised variant is run on transistor, the target will be the mean pixel value of its 173 train images, computed when its split is created), defect types bent_lead, cut_lead, damaged_case, misplaced (MVTec AD folder names).
- In this step no transistor file is read, listed or written. get_split("transistor") stops with an error saying the split is not created yet (Phase 4). The transistor split will be made by the same rule as screw (seed 42, 40 validation images) at the start of Phase 4.
- Where outputs of a non-screw category go: outputs/<category>/results and outputs/<category>/figures, and model files in outputs/checkpoints/<category>/ (already git-ignored, so .gitignore needs no change). The split file of a category is outputs/<category>/results/split.json. Screw keeps every v1 path and file name (outputs/results/split.json, outputs/results, outputs/figures, outputs/checkpoints), so v1 files can never be overwritten by another category. Nothing is produced for transistor in this step.
- Images: greyscale stays exactly as in v1 (H x W float in [0, 1], PIL bilinear to 256). Colour images are kept as 3 channels, channel-first (3 x H x W), same PIL bilinear resize to 256, scaled to [0, 1]. Masks stay greyscale with nearest-neighbour resize.
- src/data.py, src/autoencoder.py, src/patchcore.py, evaluate.py and demo.py get a category argument (default "screw"). The autoencoder gets an input-channel setting (1 for greyscale, 3 for colour) without renaming any layer, so the v1 checkpoints load unchanged (strict). PatchCore: greyscale is converted to 3 channels + ImageNet normalisation exactly as in v1; colour images pass their 3 channels with the same normalisation. The robustness perturbations of evaluate.py work per image over all channels; for greyscale they are the same operations as in v1.
- A background mask can only be requested for a category that allows it; for transistor the code stops with an error.
- Proof that v1 is unchanged (done in this step): hashes of all files in outputs/results, outputs/figures, outputs/checkpoints, outputs/analysis and outputs/v2/phase2 before and after; the 40 screw validation images re-scored with the new code and all 4 v1 models must equal <variant>_val_scores.csv (up to float noise, about 1e-6); phase2.py re-run with the new code must give the same baseline_metrics.csv and synthetic_defects.csv as committed; python evaluate.py --report-only must give identical files; both autoencoder checkpoints must load with strict=True.

### Phase 3b: candidates, decision rule and implementation (written before any candidate was built or scored)
In this step no candidate is trained, built in full or scored: only the code and checks that do not look at any synthetic or test result.
- v2 is built on the raw variants only (brightness normalisation did not help PatchCore on the real test or on the synthetic set). Baselines: v1 pc_raw for PatchCore, v1 ae_raw for the autoencoder.
- Candidates, fixed configurations (no other setting is tried, nothing is tuned after scoring):
  - P1 "pc_512": PatchCore at 512 px input (1024 -> 512 with the same 8-bit PIL bilinear pipeline as data.load_image), same backbone and layers, so the patch grid is 64 x 64 instead of 32 x 32. Bank: 280 train images x 4096 patches = 1,146,880 vectors would not fit; a random 25% of the patch vectors of each image (numpy default_rng(42)) gives 286,720 vectors, the same pool size as v1 (280 x 1024); then the same greedy coreset at 10% gives 28,672 vectors, the same bank size as v1. Heat-map: 64 x 64 patch scores -> 512 bilinear -> Gaussian sigma 8 (the same physical size as v1's sigma 4 at 256). Image score = maximum patch score, exactly as in v1 (only the resolution changes). For every metric (pixel AUROC, IoU / Dice, T_pixel, 8 px hit rate) the 512 heat-map is resized to 256 with PIL bilinear, like the images. Inherent property, not a tuned choice: at 512 the 3 x 3 patch neighbourhood covers half the physical width of v1's.
  - P2 "pc_mask": v1 pc_raw (same bank, nothing rebuilt) + background mask.
  - P3 "pc_512_mask": P1 + background mask.
  - A1 "ae_ssim": same architecture, epochs, seed, augmentation and data as v1 ae_raw; loss = 0.5 MSE + 0.5 (1 - mean SSIM). SSIM on the 256 px grey images, 11 x 11 Gaussian window with sigma 1.5, C1 = 0.01^2, C2 = 0.03^2 (data range 1), reflect padding so the local SSIM map is 256 x 256 (own torch code, no new package). Heat-map = 1 - local SSIM map, Gaussian sigma 4; score = maximum of the heat-map. Best epoch = lowest validation loss, with the same 0.5 MSE + 0.5 (1 - SSIM) loss, as in v1.
  - A2 "ae_mask": v1 ae_raw (same checkpoint, nothing retrained) + background mask.
  - A3 "ae_ssim_mask": A1 + background mask.
- Background mask (screw only; src/categories.py forbids it for transistor): computed from each image itself, no labels. The screw rule of src/synthetic.py on the 1024 px image (darker than median - 0.30, closing 6, opening 3, largest region, fill holes), then dilated by 32 px = every pixel within Euclidean distance 32 px of the screw (scipy distance_transform_edt, not binary_dilation with iterations, whose diamond shape reaches only about 23 px diagonally), then resized with nearest-neighbour to the model's input size (256, or 512 for P3), i.e. 8 px at 256. Application, after the normal prediction: heat-map pixels outside the mask are set to that heat-map's minimum (over the whole map, before masking); image score = maximum inside the mask, in each model's own score: for the autoencoder the maximum of the smoothed heat-map inside the mask; for PatchCore the maximum patch score over the patch cells that contain at least one mask pixel. The PatchCore bank and the autoencoder training are not affected by the mask (P2 and A2 need no new model). Stated risk, in advance: the synthetic set cannot show whether the mask cuts real defects at the screw edge (Phase 2, note 2); the real screw test in Phase 4 is the first check.
- Synthetic images with a mask: the mask is computed from the defective image itself at 1024 px, as it would be for a real image (no clean image exists in a real test). Technical change to src/synthetic.py: options (off by default) that also return, per synthetic image, the same defective 1024 px image resized to 512 px (for P1 / P3, same 8-bit PIL bilinear pipeline) and the background mask computed on the fly from its defective 1024 px image. It changes no random draw and no image; proof: phase2.py with defaults must still give byte-identical baseline_metrics.csv and synthetic_defects.csv.
- Thresholds of every candidate: the v1 rule on its own 40 good validation images (T_image = 99th percentile of the scores, T_pixel = 99.9th percentile of the heat-map pixels); for masked candidates on the masked validation heat-maps and scores.
- Where v2 outputs go: models in outputs/checkpoints/v2/ (git-ignored), results and figures in outputs/v2/phase3/. No v1 file is written.
- Decision rule (fixed now):
  - Primary: image AUROC, 40 good vs the 160 synthetic validation images.
  - Uncertainty: paired cluster bootstrap, 2000 resamples, seed 42 (numpy default_rng): each resample draws 40 base images with replacement; the good set is their good versions, the defect set their 4 synthetic versions (160 per resample, duplicates kept), because the 4 defects share one base image and are not independent. AUROC difference = candidate minus its baseline on the same resample.
  - A candidate beats its baseline only if ALL hold: (1) the 95% CI lower bound (2.5th percentile) of the AUROC gain is > 0; (2) its localisation hit rate (8 px, all 160, point estimate) is not lower than the baseline's by more than 0.05; (3) no synthetic type loses more than 0.10 AUROC (point estimates). Thresholds are not needed for the rule.
  - v2 for each model = the candidate with the highest primary AUROC among those that beat the baseline; if none does, v2 = v1 for that model, and this is reported as a result.
  - After scoring, only technical fixes are allowed (out of memory, chunking), never a change of settings; any fix is written here.
- Honest notes: 6 candidates are compared, so one could pass by luck; the transistor test in Phase 4 is the independent check. The 40 validation images are also the good half of the synthetic evaluation and (for ae_ssim) choose the best epoch, as in v1.
- Checks in this step (no synthetic image and no test image is scored with any candidate): v1 reproduction and hash check as in Phase 3a, with every new option off; a figure of the 40 validation screws with the dilated mask outline (outputs/v2/phase3/val_masks.png) plus a CSV per image (mask area, screw area, and the number of pixels darker than median - 0.15, a looser rule, that lie outside the mask) to check by eye and by number that no thread tip or head edge is cut; unit checks of SSIM and of the mask application on 2 validation images (shape only); a feasibility test of pc_512 with 10 TRAIN images only (time, GPU and RAM peak, extrapolation to 280 images and to scoring 200 images); the test bank is deleted, only the numbers are kept (outputs/v2/phase3/feasibility.txt).

### Phase 3c: RESULT (written after scoring, 2026-11-13)
This is a result, not a decision: the rule of Phase 3b was applied unchanged, in code (phase3c.py, run once; Phase 3b was committed before, 19bb671, and the sha256 of decisions.md and all code were logged before scoring and were unchanged after). No test image was loaded (only screw/train/good files were read). No setting was changed after scoring, and no technical fix was needed.
- Builds (train/val only): ae_ssim trained 120 epochs in 13.2 min, best epoch 119 (GPU peak 298 MB); pc_512 bank built in 2.3 min (pool 286,720 -> bank 28,672; GPU peak 723 MB, RAM peak 4.0 GB). Saved in outputs/checkpoints/v2/.
- Baselines reproduce Phase 2: validation scores max difference 4.9e-8 (pc_raw) and 4.1e-10 (ae_raw), synthetic score / T within the 5-decimal rounding of synthetic_defects.csv, thresholds identical to thresholds.csv.
- Image AUROC, 40 good vs 160 synthetic (gain over the baseline [95% paired cluster-bootstrap CI]; hit-rate change; worst per-type AUROC change):
  - pc_512: 0.736 vs 0.705, +0.031 [-0.004, +0.071]; hit rate +0.150; spot -0.050 -> criterion 1 fails.
  - pc_mask: 0.706, +0.001 [-0.023, +0.023]; +0.088; spot -0.004 -> criterion 1 fails.
  - pc_512_mask: 0.742, +0.038 [-0.0004, +0.081]; +0.169; spot -0.042 -> criterion 1 fails (the CI lower bound is just below 0).
  - ae_ssim: 0.499 vs 0.520, -0.021 [-0.045, +0.003]; -0.050; cutpaste -0.054 -> criterion 1 fails.
  - ae_mask: 0.520, +0.000 [0, 0]; 0.000 -> criterion 1 fails. The mask changed no autoencoder score: on all 200 images the autoencoder's maximum already lay inside the mask.
  - ae_ssim_mask: identical to ae_ssim (same reason) -> criterion 1 fails.
- Criteria 2 and 3 held for every candidate; criterion 1 failed for every candidate.
- SELECTION by the rule: no candidate beats its baseline, so v2 = v1 for both models: v2 PatchCore = pc_raw, v2 autoencoder = ae_raw.
- Observations only (they do not change the selection): the 512 px PatchCore variants localise much better on the synthetic defects (hit rate 0.494 -> 0.644 / 0.662, pixel AUROC 0.926 -> 0.984 / 0.987, IoU 0.091 -> 0.152 / 0.156) and gain AUROC on scratch and thread_smear but lose on spot; their AUROC gain is positive in about 96-97% of the resamples, which is not enough for the fixed criterion. The SSIM loss did not help the autoencoder, which stays at chance level on the synthetic defects.
- Outputs: outputs/v2/phase3/ (candidate_thresholds.csv, candidate_scores.csv, candidate_metrics.csv, bootstrap.csv, decision_table.csv, selection.csv, decision_forest.png, per_type_auroc.png, ae_ssim_training.png, ae_ssim_history.csv, phase3c_log.txt). Hash check: 73 earlier files (v1 outputs and checkpoints, analysis, v2/phase2, the Phase 3b files) unchanged.
